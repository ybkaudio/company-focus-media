# ④ 별도 점검 (쓴 쪽과 점검하는 쪽 나누기)

지금까지 실수 대부분은 규칙이 없어서가 아니라 있는데 놓친 것. 원고를 쓰거나 렌더한 Claude가 자기 결과를 점검하면 같은 곳을 또 놓치므로, overview를 사용자에게 보이기 **직전**에 쓰지도 렌더하지도 않은 점검자가 규칙 파일과 한 줄씩 대조함. (11/23 사용자 "정리해")

## 언제
- 제작·게시: 렌더가 끝나고 overview를 스레드에 올리기 직전, 매 편·매 재렌더.
- 원고: 탭·JSON을 넘기기 전에는 1단계(기계 점검)만 돌림.

## 1단계: 기계 점검 (몇 초)
`python3 render.py --check episodes/<stem>.json`
- 장 이름 목록, 편 번호, 사진 설명, 메인 사진 폭, 사진 중복, 어둡게·흐리게, 캡션 금지 줄(💬📌👇, 첫 댓글)을 봄. 하나라도 걸리면 고친 뒤 다시.

## 2단계: 별도 점검자 (서브에이전트)
렌더한 세션이 Agent 도구로 새 에이전트(general-purpose)를 하나 띄워 아래 프롬프트를 그대로 줌. 점검자는 고치지 않고 표만 냄.

```
너는 인스타 캐러셀 '기업집중탐구'의 점검자다. 이 편의 원고·렌더에 참여하지 않았다. 고치지 말고 어긴 곳만 찾는다.
읽을 것(전부): /home/user/company-focus-media/rules/1-wongo-common.md, 1-wongo-kiupin.md, 2-design.md, 3-upload.md 의 '캡션·음악'
점검 대상: episodes/<stem>.json (본문·제목·캡션), out/<stem>/ 의 장 이미지 01.png… (Read로 한 장씩 봄), out/<stem>/caption.txt
방법: 규칙 파일의 줄을 위에서부터 하나씩, 이 편의 모든 장에 대어 본다. 규칙이 이 편에 해당하지 않으면 건너뛴다. 사실 확인이 필요한 숫자는 "확인 필요"로만 표시한다.
출력: 어긴 곳만 표로. 열 = 장(표지=01) | 규칙(파일·줄 요약) | 어긴 내용(원문 인용) | 고칠 안. 어긴 곳이 없으면 "어긴 곳 없음" 한 줄. 표 밖의 칭찬·요약은 쓰지 않는다.
특히 볼 것: 장 제목에 사건·숫자 두 개, 이유 없이 이어진 사건("~하자"), 무엇을 보고 결정했나 빠진 투자·계약, 성격 모를 돈, 처음 나오는 인물 소개, 회사·인물 표기, 내용 사진 대신 프로필 사진, 사진 설명이 사진과 다름, 사진이 좌우를 안 채움, 떠날 때 숫자 2개·행보 줄, 마무리 3줄이 구체 사건과 붙었나, 캡션 순서와 금지 줄.
```

## 3단계: 고치고 보이기
- 표의 줄을 고침: 글은 원고 스레드에 커밋 요청(또는 사용자 규칙상 제작이 고치는 사진·설명·배치는 직접), 다시 렌더 → 1단계 다시.
- 고친 뒤에만 overview를 스레드에 올림. 메시지 첫머리에 "점검: 어긴 곳 N개 고침, 남은 확인 필요 M개"를 한 줄로.
- 점검자가 규칙 자체가 모호하다고 한 줄은 코디네이터에 한 줄로 알림(규칙 파일 고칠 후보).
