- 2026-11-14 사용자(피터 틸 편 v1 지적): "내용이 떡하니 있는데도 프로필 사진을 배경으로 깔아두지 말라". 우선순위 1) 내용+인물 함께 2) 내용이 드러나는 사진(사건·제품·로고·원리) 3) 그 당시 인물 4) 못 찾으면 나중에 다시 찾거나 AI·직접 만든 그림.
- 같은 날: "사진별 아래에 작은 글씨 쓰는 거 잊지 않았지? … 이런 실수 또 보고 싶지 않아" → 사진 있는 모든 장에 photo_note(무엇·누구·연도, 합성·그림이면 밝힘). render.py가 빠진 장을 "경고:"로 출력(4afd8b7) → 렌더 출력에 경고가 있으면 고치고 다시 렌더.
- 다른 편 사진도 내용에 맞으면 재사용 가능(피터 틸 06장 = 머스크·PayPal 편 컴퓨터 앞 사진).
- 이 환경에선 이미지 검색 긁어오기가 막힘(자동 권한 거부). 쓸 수 있는 건 위키미디어 공용, 기사 페이지 속 이미지, 저장소의 다른 편 사진, 직접 만든 그림·합성.

- 2026-11-14 피터 틸 편 v2 피드백(사용자 "네 피드백 아주 좋았어", 앞으로 모든 편 적용):
  - 창업 장에 회사 건물·본사 사진은 약함. 1) 창업자 팀 사진에 로고가 보이는 것 2) 없으면 로고만(어두운 배경에 직접 배치)을 쓴다(11장 Palantir 본사 → 로고로 교체, bb40ce7).
  - 두 사람이 함께 찍힌 사진이 없으면 그 당시 두 사람 사진(또는 인물+사건 사진)을 나란히 붙인 합성은 괜찮다(12장 틸·저커버그, 13장 틸·Falcon 1 승인). photo_note에 "나란히 붙임" 밝힘.
  - overview를 보여 줄 때 약한 장과 이유를 먼저 스스로 짚는다(사용자가 이 방식을 좋아함).

**Why:** 카드 내용을 사진이 보여 줘야 하고, 사진 설명은 사용자가 이미 정한 규칙인데 v1에서 빠뜨림.
**How to apply:** 사진 배치 때마다 장 내용부터 보고 고르고, 렌더 전 photo_note 확인. 원문 규칙 /mnt/project-files/wongo/composition-rules.md. [[kiup-photo-and-link-rules]] [[self-sourced-photos-commons]]

- 2026-11-15 사용자(SpaceX 편 overview): "이미지 설명 어디갔어!!! 이런 실수 한두번이냐" → 대기 편 #23·#25·#26 전부 photo_note가 없었음(11/14 규칙 전에 렌더한 편). 모두 채워 재렌더(526d0af). render.py는 이제 photo_note 없으면 경고가 아니라 렌더를 멈춤. 렌더 전 대기열 전체를 점검하는 습관.
- 2026-11-15 사용자(카프 11·16장): "왜 자꾸 스티커도 아닌 메인 사진을 이렇게 작게 쓰는 거야" → 메인 사진은 최소 좌우 끝까지. comp.place 기본 width=1600, 헤더 줄 아래 top≈290, 제목 겹침은 photo_fade로. render.py가 4:5 합성에서 내용 폭 90% 미만이면 렌더 중단(로고만·직접 그린 그래프는 photo_small: true 예외).
