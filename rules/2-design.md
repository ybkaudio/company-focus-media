# ② 디자인 규칙 (사진 고르기·배치·렌더)

⚙ 표시 = render.py가 자동으로 렌더를 멈춤(`python3 render.py --check episodes/X.json`으로 렌더 없이 미리 확인).

## 사진 고르기
- 우선순위: 1) 그 장 내용과 인물이 같이 있는 사진 2) 내용이 드러나는 사진(사건·제품·로고·원리) 3) 그 장 시기·내용과 직접 이어지는 장소·물건·문서 사진(고향·학교·첫 사무실·당시 제품·신문 등) 4) 그 당시 인물 사진. 내용 사진이 있는데 프로필 사진을 깔지 않음. (11/14 틸 v1: Facebook 투자 장 = 틸+저커버그, 상장 장 = 상장 당일)
- 연관 사진 찾기는 절대 포기하지 않음. 다른 시기 인물 사진·장 내용과 상관없는 사진으로 '대신' 채우지 않음. 인물 사진이 없으면 그 장 내용과 이어지는 장소·물건·문서 사진을 끝까지 찾음. (11/23 사용자 "많이 실망": 에번 윌리엄스 1990년대 장에 2013년 사진 → 고향 네브래스카 사진으로 교체)
- 창업 장: 로고가 보이는 창업자 팀 사진 > 로고만. 건물·본사 사진은 쓰지 않음. (11/14 틸 v2 11장)
- 두 사람이 함께 찍힌 사진이 없으면 그 당시 두 사진을 나란히 붙인 합성 가능, 설명에 "나란히 붙임". (11/14 틸 12·13장)
- 제목이 정해진 편은 제작이 직접 사진을 고름(저작권 걸려도 됨). 사용자가 사진을 올리면 그 사진이 우선. (11/23 13:43 점검 흐름)
- 사용자가 올린 사진은 올린 순서 그대로(첫 사진 = 표지), 사용자가 정한 사진은 바꾸지 않음. 걱정되면 넣고 한 줄로만 알림. "N번은 M장 스티커로"도 그대로. (11/11 머스크·PayPal "순서 바꾸지 마")
- 다시 쓰는 편은 기존 사진을 새 장 번호로 `git mv`해 재사용, 안 쓰는 건 photos/spare/. (11/08)
- ⚙ 한 편 안에서 같은 사진을 두 장에 쓰지 않음. 다른 편 사진은 내용이 맞으면 재사용 가능. (11/11 "재탕하냐?")
- 점검: 동명·가족 인물 혼동(공식 자료로 대조), 주인공으로 오해될 다른 인물은 크롭, AI 생성 의심(글자 깨짐·인원수), 표지 가로 1000px 미만, 워터마크·다른 계정 문구는 크롭. 누군지 확실치 않으면 코디네이터로 확인. 사용자가 고른 장난스러운 사진은 그대로. (11/09 LEGO, 11/10 웨인·글래스, 11/10 저커버그)

## 배치
- 기본은 배경 꽉 채우기. 약 1.85:1 이상 가로로 긴 사진만 위쪽에 가로를 채우고 아래는 검정으로 이음. 1.5:1 사진·화면 캡처도 꽉 채움. (11/10 시스트롬)
- ⚙ 스티커가 아닌 메인 사진은 최소 좌우 끝까지(4:5 합성은 내용 폭 90% 이상). 예외는 `photo_small: true`(로고만 놓는 장, 직접 그린 그래프). (11/15 카프 11·16장)
- ⚙ 사진을 어둡게·흐리게 처리하지 않음(`shade: "strong"`, filter·brightness·blur 계열 칸 금지). 원본 밝기·선명도 그대로, 가독성은 그라데이션으로만. 워터마크는 크롭, 흐림은 그 부분에만 마지막 수단. (11/09 Amazon·현대 "너무 어둡고 흐리다")
- ⚙ `photo_fade`(사진 아래쪽 검정 페이드)는 사용자가 그 장을 콕 집어 말할 때만. 합성 사진이 제목을 가려도 예외 없음(사진 크기·위치로 해결). JSON에 `photo_fade_by_user: "MM/DD 사용자 지시"`가 없으면 렌더가 멈춤. (11/12 젠슨 황 10·11장, 11/23 사용자 "내가 말한 장만, 카프 편은 잘못")
- 로고 하나만 있는 배경: 로고를 가로 정중앙, 세로는 제목 위 빈 공간 가운데. (11/11 필 나이트 03)
- 표지 로고 스티커: 표지 사진에 로고가 안 보일 때만. 중심 가로 820·세로 1137px, 정사각형 최대 260·가로형 360. 제목이 짧아 사용자가 위치를 정하면 `fixed: true`. (11/11)
- 중간 장 스티커는 의미 있을 때만, top 190 이상. (11/09 LEGO·삼성)
- 모든 장 사진(빈 장 없음, 그래프·캡처는 직접 만듦), 마무리 = 아직 안 쓴 가장 의미 있는 실제 사진, 로고는 표지 장 안: 원고 문서 단계 규칙은 [1-wongo-common.md](1-wongo-common.md) 6. 렌더도 같음(마무리 배경에 로고 금지). (11/23 사용자, Anthropic 편)
- 기업집중탐구 모든 편 맨 끝 = 고정 홍보 장(render.py가 자동으로 붙임, 사진·문구는 assets/promo/: 위 6분할 머스크·잡스·게이츠·저커버그·베이조스·젠슨 황, "아이디어 하나가 / 대기업이 되기까지", 버튼 "팔로우하고 업데이트 받기"). 마무리 장에는 팔로우 버튼을 넣지 않음. 이미 다른 곳에 장 수가 고정 예약된 편만 JSON에 "no_promo": true. (11/23 사용자 "A Grid … 마지막 페이지로서 이제부터 고정", Pizza Hut만 BS 10장 예약이라 제외)

## 자동 제작 (00시 편성 스캔이 넘긴 편, 11/23 사용자 "제목 입력 = 최종 합격, 렌더 결과 안 봐도 됨")
- ⚙ **모든 수정은 Google 문서에서, 최종 렌더는 문서에 있는 그대로**(사진·장 제목·본문·회사 가치 줄·숫자·마무리 줄·사진 설명·설명란·음악). 렌더 단계에서 사진을 바꾸거나 글을 JSON에서 따로 고치지 않음. 고칠 게 생기면(레이아웃 넘침, --check 걸림, 사진 설명 빔) 문서를 고친 뒤 doc2episode.py를 다시 돌림. 사진 합성·크롭·위치·스티커 같은 배치만 렌더 단계에서 함. (11/25 사용자 "모든 수정은 Google 문서에서 하고, 최종 렌더는 문서에 있는 그대로 함")
- 렌더 시작 조건은 사용자가 표지 장 `표지 제목:`을 직접 쓴 것 하나뿐(`표지 제목 후보(참고용)` top3는 원고가 채워 두지만 렌더 조건 아님, doc2episode.py가 `표지 제목:`이 비면 멈춤). 사용자가 "제목 적었어"라고 하면 00시를 기다리지 않고 그 턴에 아래 1~4를 바로 함(제목 찬 탭 중 schedule.json에 없는 것 전부, 문서 앞 순). (11/25 사용자)
1. 공동 문서를 `read_doc` → `python3 publisher/doc2episode.py <결과 파일> "<탭 제목>" <stem>`으로 바뀔 것을 보고 `--apply`(문서가 원본: 사용자가 바꾼 사진·제목·본문을 JSON·photos로 가져옴). 장 수가 다르면 원고에 넘김. '설명 필요'가 나오면(사용자가 사진을 바꾸고 설명 줄을 지운 장) 그 사진을 직접 보고 무엇·누구·연도 설명을 써서 문서 '사진 설명:' 줄과 JSON photo_note에 넣은 뒤 렌더함. 추측으로 쓰지 말고 모르면 사진 출처를 찾아 확인. (11/23 사용자 "설명란 없는 사진이 있다면 네가 직접 렌더 전에 설명을 추가해줘")
2. 사진 배치를 이 파일 '배치'대로 손봄(합성·크롭·스티커) → `render.py --check` → 렌더 → `export.py`.
3. rules/4-review.md 2단계 별도 점검 → 어긴 곳 고치고 다시 1단계. 사용자에게 overview를 보이지 않음(확인 필요만 코디네이터로).
4. `python3 publisher/sched.py slot <stem> "인물 · 회사"`(대기열 맨 뒤) → 커밋·push(사진은 `git add -f`). 사용자가 맥북 Aside에 게시 프롬프트를 넣을 때 차례대로 게시(3-upload, 11/25).
