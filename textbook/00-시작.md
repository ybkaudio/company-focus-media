# 0장. 이 교과서를 쓰는 법

기업집중탐구(@company.focus)와 AI기업집중탐구(@aicompany.focus)의 작업 교과서. **규칙의 원본은 이 폴더 하나뿐임.** 메모리·스킬·인수인계·Notion·트리거 프롬프트에는 규칙 본문을 두지 않고 이 폴더의 장 번호만 가리킴. (11/26 사용자 "하나의 교과서를 만들어서 따르라")

## 0-1. 모든 일의 첫 단계 (예외 없음)
1. 지금 하려는 일이 아래 표의 몇 장인지 찾음.
2. **그 장을 처음부터 끝까지 읽음.** 기억이나 메모리로 대신하지 않음. 지난번에 읽었어도 다시 읽음(그사이 개정됐을 수 있음).
3. 편을 다루는 일이면 진행표부터 엶: `python3 tools/step.py show <stem>`. 진행표가 가리키는 단계만 함. 앞 단계가 안 끝났으면 그 단계부터.
4. 장의 **순서**대로 하고, **통과 기준**을 다 채운 뒤 `python3 tools/step.py done <stem> <단계>`. 검사 명령이 있으면 step.py가 돌려 보고, 걸리면 다음 단계로 못 감.
5. 하다가 교과서에 없는 판단이 나오면: 사용자가 이미 정한 방향(1장 목표)으로 추천안을 골라 진행하고, 끝난 뒤 12장 개정 절차로 그 판단을 교과서에 적을지 코디네이터에 한 줄로 알림.

## 0-3. 줄 표시 읽는 법
- 줄 끝 괄호 `(11/14 틸 15)` = 정한 날짜(2026)와 예시 편·장. **규칙끼리 부딪치면 날짜가 늦은 쪽.**
- `[기업인]` = 기업집중탐구에만, `[AI]` = AI기업집중탐구에만. 표시 없는 줄 = 두 계정 공통. AI 합본은 `[기업인]` 줄을 빼고 만듦(`python3 publisher/make_ai_pack.py`).
- ⚙ = 기계가 막음(`python3 render.py --check episodes/<stem>.json`이 멈춤). ⚙가 없는 규칙은 사람이 지켜야 하므로 통과 기준 체크 칸에 들어 있음.
- 사용자가 직접 쓴 문구·고른 사진은 어떤 규칙보다 우선(9장).

## 0-4. 부서
- 프로젝트는 부서 스레드로 나눔: ✍ 원고(2~8장) · 🖼 제작·게시(10~11장) · 🗂 편성(11장 대기열·예약 작업). 한 스레드는 자기 장만 함. 다른 부서 일이 생기면 코디네이터로 넘김. (사용자 계정 선호 '부서제')
- 부서끼리 넘길 때는 진행표(step.py)가 기준. "넘겼어요"라는 말보다 진행표의 단계가 우선.

## 0-5. 교과서 밖에 두는 것 (규칙 아님)
- 진행 상황: `episodes/<stem>.steps.json`(진행표), `publisher/schedule.json`(대기열), Notion '인스타 게시 기록'.
- 자원 위치(문서 ID·링크): 프로젝트 메모리.
- 옛 원문(근거 찾을 때만): `rules/archive/`, `/mnt/project-files/archive/`.
