# 8장. 문서 올리기 (공동 구글 문서 탭 + JSON + 설명란·음악)

## 들어오는 것
- 본문·제목·사진·사진 설명.

## 순서
1. 원고 전체를 텍스트 파일로 먼저 씀(스크래치 폴더). 사진 자리는 `[[IMG:NN]]` 한 줄.
2. 설명란·음악 추천·작성 메모를 아래 규칙대로 씀.
3. 공동 구글 문서(16w0KTBVATdwjiNuUlaoKIVjDcRc0CmgvAKbI2xlIzc0) **맨 끝에** 탭 추가: [기업인] `[기업인] 인물명` / [AI] `[AI] 회사명`. 별도 문서를 새로 만들지 않음. 새 편이면 `update_doc`의 `addDocumentTab`, 있는 탭이면 그 탭 본문을 지우고(`deleteContentRange`, tabId) 다시 씀. 사용자가 손으로 고친 문장·사진이 있으면 지우기 전에 뽑아 두고 그대로 살림. (11/23)
4. `insertText`(location에 tabId) → `read_doc`(결과는 파일로 저장됨)을 python으로 읽어 문단 인덱스를 구함.
5. 서식 요청 한 번: 첫 줄 HEADING_1, "■"로 시작하는 줄 HEADING_2, '장 제목:'·'숫자 N:' 줄 굵게, '사진 설명:' 줄 9pt 기울임. 둘째 "■"부터 `pageBreakBefore: true`(장마다 새 페이지). (11/23)
6. 이미지 넣기 한 번: `[[IMG:NN]]`을 **문서 뒤쪽부터** `deleteContentRange` → 같은 위치에 `insertInlineImage`(폭 360pt, 표지 로고 240pt). 지워진 파일·큰 원본은 배치 전체가 실패하므로 큰 사진은 `/thumb/.../1280px-` 주소로, 실패하면 하나씩 보내 그 장만 다른 후보로. (11/23)
   - 도구 호출에 한글을 그대로 보내면 글자가 깨짐(그만뒀다→그만둬다). 문서에 쓰는 한글은 \u 이스케이프로 보내고, 깨진 글자는 replaceAllText + tabsCriteria로 고침. (11/23)
7. 같은 내용을 `episodes/<stem>.json`에(아래 JSON 칸). [기업인] `plans/<stem>.md`는 `plan_md.py`로.
8. 1차 기계 점검: `python3 render.py --check episodes/<stem>.json` → 걸리면 문서와 JSON을 함께 고치고 다시.
9. 사진 지문 저장: `read_doc` 결과로 `python3 publisher/photo_fp.py <결과 파일> --save`(9장에서 사용자 교체 감지용). (11/26)
10. 진행표를 9단계로: `python3 tools/step.py done <stem> 8`.

## 문서 모양 (두 계정 공통, 본보기 = [AI] Anthropic 테스트 원고 https://docs.google.com/document/d/1WSuovwgqQjITPS2_eP9HWgWfPhMQhoPCBtzEYzALma8/edit , 11/23 사용자 "기본 템플릿으로 고정")
- 맨 위: 제목1 "[계정] 이름 · 회사" → 굵게 한 줄(순위·장 수·설립 등) → 기준일·확인 원칙 한 줄. `제목:`·`상태:` 줄은 두지 않음. 진행 상태(제목 대기·렌더 중·게시됨)는 문서에 쓰지 않음. (11/23)
- 장마다 제목2 "■ NN 장 이름 · 시기 · 나이"([AI] "설립 N년차"), 장마다 새 페이지. 표지가 ■ 01. (11/23)
- 표지(■ 01 표지): `표지 제목: `(빈칸) → `표지 제목 후보(참고용):` ①②③ → 표지 사진 + `사진 설명:` → 로고 사진 + `사진 설명:`. (11/23)
- 나머지 장: 굵게 `장 제목:` → `본문:` → [기업인] `회사 가치 줄:` → 사진 → `사진 설명:`. 떠날 때·정점(stats)·[AI] 지금 장은 `숫자 1:`·`숫자 2:`(굵게)·`한 줄:` → 사진. (11/23)
- 끝: 제목2 `■ 설명란` → `■ 음악 추천` → `■ 작성 메모 (게시 전 삭제)`(출처 목록, 공동 문서와 다른 점, 뺀 일화와 이유, 출처가 엇갈린 곳). (11/23)

## JSON 칸 (episodes/<stem>.json)
- `when`: [기업인] "연도 · 나이"(나이 = 연도 − 출생 연도로 모든 장 같은 방식) / [AI] "연도 · 설립 N년차". (11/15 카프)
- [기업인] `value`: 표지·마무리를 뺀 장마다 "회사 가치 약 N(기준)". 설립 전 "회사 설립 전", 다른 회사 시절은 괄호에 회사 이름, 추정 방법은 출처 줄. (11/11)
- [기업인] `company_ko` 필수(표지 "인물 · 회사" 줄). 스타벅스 등 예외는 부록 B. (11/08, 11/13)
- `no`·편 번호(#NN)는 넣지 않음. (11/13)
- `music`: "곡 – 가수 (이유) / 없으면 검색어 '…'". (11/09, 11/23)
- [기업인] `photo_hint`: 7장 우선순위대로 "1) … / 2) … / 3) …", 영어(한국 기업 편은 한국어). 표지는 "COVER LOGO: 회사 로고 투명 PNG(표지 사진에 로고가 또렷하면 생략)". (11/09, 11/11, 11/14)
- `photo_note`: 7장 사진 설명 그대로.

## 설명란 (caption)
- 순서: ① 훅 2줄(반전·대비 하나 + 숫자) ② "연도, 사실." 짧은 문단 3~5개(습니다체, 명사 종결 섞기) ③ 인물 실제 한마디(있으면) ④ 존댓말 질문 한 줄 + 다음 줄 "댓글로 알려 주세요." ⑤ 🔗 연관 편 한 줄(있을 때만) ⑥ 해시태그로 끝. [기업인] #기업집중탐구 먼저 / [AI] 자기 계정 해시태그 먼저. (11/11 개편, 11/14, 11/23 사용자 "규칙대로")
- 화제 편은 설명란 첫 줄을 이슈와 잇기. (11/12)
- [기업인] 묶음 편: 해시태그 위에 "🔗 [묶음] 시리즈. 관계 + 그 이야기는 ○○ · ○○ 편에서." 묶음 해시태그는 #기업집중탐구 바로 뒤. (11/10)
- 출처는 설명란에 넣지 않음. 작성 메모와 Notion 원고 DB에만. render.py가 '출처' 블록을 빼고 caption.txt를 씀. (11/23 사용자 "출처 그냥 안 넣으면 안 되나?")
- ⚙ 넣지 않음: 💬·📌·👇 줄, 첫 댓글(first_comment), 투표, 이모지 남발. (11/14)
- ⚙ 길이: 전체 2,000자 안팎, **2,200자 넘으면 게시 실패**. 넘으면 연도 문단을 줄임. (11/24 카프 2,368자 게시 실패)

## 음악 추천
- 인지도로 고르지 않음. 그 편의 핵심 장면·감정과 가사·제목·분위기로 이어지는 곡, 누구나 아는 대표 히트곡은 피함. 이유에 어느 장면과 이어지는지 적음 + 대안 1곡. (11/23 사용자 "왜케 유명한 걸로만 골라", 예: 윌리엄스 고향 → Nebraska – Bruce Springsteen)

## 통과 기준
- [ ] 탭이 문서 맨 끝, 탭 이름 형식 맞음, 별도 문서 없음
- [ ] 맨 위 `제목:`·`상태:` 줄 없음, 장마다 새 페이지
- [ ] 모든 장 사진 + 사진 설명이 문서에 들어감
- [ ] 설명란 순서 ①~⑥, 출처 없음, 2,200자 이하
- [ ] 음악: 장면과 이어지는 이유 + 대안 1곡
- [ ] ⚙ `python3 render.py --check episodes/<stem>.json` 통과
- [ ] [기업인] ⚙ 자체 점검(render.py `ch8_check`, 11/26 Google 별도 점검 40건에서): 사진 설명 첫 문장에 연도 · 장 제목에 '달러'·'%' 두 번 없음 · 떠날 때 바로 앞 장 = 정점·상장 등 성공담(밀려난 편은 갈등) · 떠날 때 본문 끝 = 떠난 뒤 행보 · 설명란 훅 2줄에 숫자, 습니다체, '댓글로 알려 주세요.' 따로 한 줄, 출처 없음, #기업집중탐구 먼저·묶음 해시태그 바로 뒤 · 음악 '대안:'
- [ ] [기업인] 기계로 못 재는 것 직접 대어 봄(같은 점검에서 걸린 것): 남의 결정마다 무엇을 보고(5장) · 처음 나오는 인물·회사 소개(5장) · 상장 장 매출·순이익(5장) · 장 이름이 내용과 맞음(4장) · 사진 = 그 장 시기·내용(7장) · 마무리 3줄에 구체 사건(4장)
- [ ] `photo_fp.py --save` 함
