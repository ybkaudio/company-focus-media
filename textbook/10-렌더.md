# 10장. 렌더·최종 점검

## 언제
- 매일 00:00 스캔이 `표지 제목:` 찬 탭을 넘길 때(문서 앞 = 오래된 순, schedule.json·Notion '[렌더 요청'에 없는 탭 전부), 또는 사용자가 "제목 적었어"라고 할 때 바로. (11/23, 11/25)

## 들어오는 것
- 공동 문서의 그 탭(= 원본). 렌더 결과를 사용자에게 보이지 않음. (11/23)

## 순서
0. **제목 학습 기록**: 학습자료 문서도 read_doc → `python3 publisher/title_log.py <공동 문서 결과> <학습자료 결과> "[기업인] 인물" "인물 · 회사" --lesson "<후보와 최종 문구를 비교해 배운 점 한 줄>"` → 나온 requests를 학습자료 update_doc. 같은 편·같은 문구가 이미 있으면 [] (건너뜀). (11/26 사용자 "루틴으로")
1. **문서 → JSON**: 공동 문서 `read_doc` → `python3 publisher/photo_fp.py <결과 파일>`(사용자 사진 교체 확인. '사용자 교체'가 나오면 새 사진을 직접 보고 7장 '배운 점'에 한 줄 + 사진 설명 확인 → `--save`) → `python3 publisher/doc2episode.py <결과 파일> "<탭 제목>" <stem>`로 바뀔 것을 보고 `--apply`. (11/25, 11/26)
   - 장 수가 다르면 원고에 넘김.
   - '설명 필요'(사용자가 사진을 바꾸고 설명 줄을 지운 장)가 나오면 그 사진을 직접 보고 무엇·누구·연도 설명을 써서 **문서 '사진 설명:' 줄과 JSON photo_note 둘 다**에 넣음. 추측 금지, 모르면 출처를 찾아 확인. 새 이름엔 (누구). (11/23 사용자)
2. **배치**: 아래 '배치' 규칙대로 합성·크롭·스티커만 손봄 → `python3 render.py --check episodes/<stem>.json` → 렌더 → `python3 publisher/export.py <stem>`(posts/<stem>-final + overview).
3. **별도 점검**: 아래 '별도 점검' 프롬프트로 새 서브에이전트 → 표의 줄을 고침 → 다시 2번. 확인 필요만 코디네이터로.
4. `python3 tools/step.py done <stem> 10` → 11장.

## 규칙: 문서가 원본
- ⚙ **모든 수정은 Google 문서에서, 최종 렌더는 문서에 있는 그대로**(사진·장 제목·본문·회사 가치 줄·숫자·마무리 줄·사진 설명·설명란·음악). 렌더 단계에서 사진을 바꾸거나 글을 JSON에서만 고치지 않음. 고칠 게 생기면(레이아웃 넘침, --check 걸림, 사진 설명 빔) 문서를 고친 뒤 doc2episode.py를 다시. 배치(합성·크롭·위치·스티커)만 렌더 단계에서. (11/25 사용자)

## 규칙: 배치
- ⚙ 세로로 긴 사진(가로:세로 1:1 미만)은 배경 꽉 채우기. **가로로 긴 사진(1:1 이상, 화면 캡처 포함)은 확대·자르기 없이 가로 폭에 딱 맞게 키워 위쪽에 놓고, 남는 아래 공간은 검정 그라데이션.** 핵심 인물·물건이 잘리지 않게. 가로 사진에 `bgsize`(확대)가 있으면 --check가 멈춤. (11/26 사용자)
- ⚙ 스티커가 아닌 메인 사진은 최소 좌우 끝까지(4:5 합성은 내용 폭 90% 이상). 예외 `photo_small: true`(로고만 놓는 장, 직접 그린 그래프). (11/15 카프 11·16장)
- ⚙ 사진을 어둡게·흐리게 처리하지 않음(`shade: "strong"`, filter·brightness·blur 계열 금지). 가독성은 그라데이션으로만. 워터마크는 크롭, 흐림은 그 부분에만 마지막 수단. (11/09 "너무 어둡고 흐리다")
- ⚙ `photo_fade`는 사용자가 그 장을 콕 집어 말할 때만, JSON에 `photo_fade_by_user: "MM/DD 사용자 지시"` 필수. 합성 사진이 제목을 가려도 사진 크기·위치로 해결. (11/12 젠슨 황 10·11장, 11/23)
- 로고 하나만 있는 배경: 로고를 가로 정중앙, 세로는 제목 위 빈 공간 가운데. (11/11 필 나이트 03)
- 표지 로고 스티커: 표지 사진에 로고가 안 보일 때만. 중심 가로 820·세로 1137px, 정사각형 최대 260·가로형 360. 제목이 짧아 사용자가 위치를 정하면 `fixed: true`. (11/11)
- 중간 장 스티커는 의미 있을 때만, top 190 이상. (11/09)
- 마무리 배경에 로고 금지(7장). (11/23)
- [기업인] 모든 편 맨 끝 = 고정 홍보 장(render.py가 자동으로 붙임, assets/promo/: 6분할 머스크·잡스·게이츠·저커버그·베이조스·젠슨 황, "아이디어 하나가 / 대기업이 되기까지", 버튼 "팔로우하고 업데이트 받기"). 마무리 장에는 팔로우 버튼 없음. 장 수가 고정 예약된 편만 `"no_promo": true`. (11/23) [AI] 홍보 장은 부록 A.

## 별도 점검 (쓴 쪽 ≠ 점검하는 쪽)
렌더한 세션이 Agent 도구로 새 general-purpose 에이전트를 하나 띄워 아래를 그대로 줌. 점검자는 고치지 않고 표만 냄. (11/23 "정리해": 실수 대부분은 규칙이 있는데 놓친 것)

```
너는 인스타 캐러셀 '기업집중탐구'의 점검자다. 이 편의 원고·렌더에 참여하지 않았다. 고치지 말고 어긴 곳만 찾는다.
읽을 것(전부): /home/user/company-focus-media/textbook/ 의 01·04·05·06·07·08·10장
점검 대상: episodes/<stem>.json (본문·제목·캡션), out/<stem>/ 의 장 이미지 01.png… (Read로 한 장씩 봄), out/<stem>/caption.txt
방법: 각 장의 '규칙'과 '통과 기준' 줄을 위에서부터 하나씩, 이 편의 모든 장에 대어 본다. [AI] 줄은 건너뛴다. 사실 확인이 필요한 숫자는 "확인 필요"로만 표시한다.
출력: 어긴 곳만 표로. 열 = 장(표지=01) | 교과서 장·줄 요약 | 어긴 내용(원문 인용) | 고칠 안. 없으면 "어긴 곳 없음" 한 줄. 칭찬·요약은 쓰지 않는다.
특히 볼 것: 장 제목에 사건·숫자 두 개, '-다' 절반 초과, 제목 속 낯선 영어 회사명, 이유 없이 이어진 사건("~하자"), 무엇을 보고 결정했나 빠진 투자·계약, 성격 모를 돈, 처음 나오는 인물 소개, 내용 사진 대신 프로필 사진, 다른 시기 사진, 사진 설명이 사진과 다름, 사진 설명 속 (누구) 빠진 이름, 사진이 좌우를 안 채움, 떠날 때·정점 숫자 2개·행보 줄, 끝 장 순서(위기 → 정점 → 마무리), 마무리 3줄이 구체 사건과 붙었나, 캡션 순서·금지 줄·2,200자.
```
- 표의 줄을 고침(글·사진 설명은 문서에서 → 1번부터 다시). 보고할 일이 있으면 첫머리 "점검: 어긴 곳 N개 고침, 남은 확인 필요 M개". 규칙 자체가 모호하다는 줄은 12장 개정 후보로 코디네이터에.
