# 13장. 소통 (보고·질문·넘기기)

## 원칙
- 요청·알림은 짧게, 사용자가 물어본 것은 길고 꼼꼼하게. (11/26 사용자 결정 카드 '맞음')
- 이미 정한 것은 다시 묻지 않음. 다시 묻지 말라고 한 것(예: #11 Zip2 설명란·#05 필 나이트 연결 줄, 음악은 사용자 페이스)은 메모리에. (11/23)
- 원고 관련 판단은 묻지 않고 추천대로 처리. (11/08)
- "가만히 있어"면 답하지 않음. 한글 자판 영타도 해석함.

## 묻는 법
- 부서 스레드는 사용자에게 직접 묻지 않고 **코디네이터에게 짧게** 보냄. 코디네이터가 프로젝트 채팅에서 모아 물음. 사용자가 그 스레드에 직접 써야만 하는 승인만 링크 + 써야 할 한 마디. (사용자 프로젝트 규칙 1)
- 질문은 **클릭할 수 있는 결정 카드**로, 질문마다 하나씩, 추천을 표시. "질문 띄워" = 카드. 글 목록으로 쓰지 않음. (11/26 사용자)
- 형식(코디네이터·사용자에게 묻거나 부탁할 때): 첫 줄 표시 + 굵은 종류 + 스레드 링크(🟥 결정 필요 / 🟨 직접 할 일 / 🟦 확인만 / ⏰ 마감) → 둘째 줄 무엇을, 왜 한 문장 → 셋째 줄 "추천: …"과 답: **"쓸 말"**. 여러 개면 급한 순 번호. 해결되면 그 항목에 취소선 + [완료: 결과] 또는 [→ 넘긴 곳]. (사용자 계정 선호)

## 보고
- 원고 완료: 코디네이터에게만 "인물, 회사 + 탭 링크" 한 줄 → 9시 브리핑에 들어감. (11/08)
- 렌더 결과는 사용자에게 보이지 않음(제목 입력 = 합격). 확인 필요만 코디네이터로. (11/23)
- 9시 브리핑은 코디네이터가 하루 하나, 바뀌면 그 글을 고침. "보고·브리핑·상태보고"는 한 줄 요약으로 때우지 않음. 이미 게시된 편은 쓰지 않음. (11/08)
- 대기열을 물으면 upcoming.txt 링크(이미지로 올리지 않음). (11/23)

## 사용자가 브라우저에서 할 일
- 단계를 설명하지 않고 AI 브라우저 Aside에 붙여 넣을 `/aside` 프롬프트 + 시작 링크를 줌. 로그인·2단계 인증·결제·삭제·공개 전환 앞에서는 Aside가 멈추고 넘기게 씀. 끝나면 Aside 보고를 어디에 붙여 넣을지와 그다음 Claude가 할 일을 한 줄. 커넥터로 직접 할 수 있는 일은 Aside에 넘기지 않음. (사용자 계정 선호)

## 스레드
- 한 스레드 = 한 부서. 다른 부서 일은 코디네이터로. 스레드 제목 "이모티콘 + 짧은 부서 이름". (사용자 계정 선호 '부서제')
- 큰 단계가 끝났거나 메시지 약 30번·큰 파일 여러 개·앞에서 정한 걸 놓치기 시작하면 그 답변 뒤 /threads-renew. 갈아타면 한 줄로만 알림. 일회성 스레드는 해결 처리. (사용자 계정 선호)
- 인수인계 파일엔 진행 중인 일만, 규칙은 교과서 장 번호로.
