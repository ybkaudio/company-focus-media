# 부록 A. AI기업집중탐구(@aicompany.focus)만의 것 [AI]

이 부록 전체가 [AI]. 원고 단계(1~8장)의 AI 차이는 각 장의 `[AI]` 줄에 있음. 여기엔 AI 계정의 게시·홍보 장·작업 구조만 둠. (11/23)

| 기업집중탐구 | AI기업집중탐구 |
|---|---|
| 주인공 = 창업자 한 명 | 주인공 = 회사, 장마다 결정한 사람 한 명 |
| 끝 = 떠날 때(떠날 때 가치 + 기간) | 끝 = '지금'(최근 회사 가치 기준·연월 + 설립부터 기간) |
| 마무리 3줄 = 인물의 가장 대단한 면모 | 마무리 3줄 = 회사가 지금 자리에 온 이유 |
| 장 위 '연도 · 나이' | '연도 · 설립 N년차' |
| 탭 `[기업인] 인물명` | 탭 `[AI] 회사명` |
| 게시: 맥북 Aside에 붙여 넣을 때마다 1편(11장) | 게시: 6개 슬롯 루틴(A-1) |

## A-1. 자동 흐름·업로드
**맨 앞 줄: 계정 확인.** 게시 화면에서 로그인된 계정이 AI기업집중탐구(@aicompany.focus)인지 눈으로 확인한 뒤에만 누름. 다르거나 확인이 안 되면 아무것도 하지 않고 멈춘 뒤 사용자에게. 기업집중탐구(@company.focus)에는 절대 게시하지 않음. 공유 버튼 직전에 한 번 더 확인. (11/23)

### 하루 흐름 (매일 00:00 KST 한 번)
1. **원고 대기열 확인**: 공동 구글 문서(16w0KTBVATdwjiNuUlaoKIVjDcRc0CmgvAKbI2xlIzc0)의 `[AI] 회사명` 탭 중 표지 장 `표지 제목:`이 빈 탭 = 원고 대기열. **5편 미만이면** 모자란 만큼 새 원고를 씀(교과서 2~8장, 형식은 Anthropic 템플릿, 모든 장 사진 포함) → 문서 맨 끝에 탭 추가 → 넘기기 전 10장 별도 점검(원고판). (11/23)
2. **사용자 점검**: 사용자가 탭을 읽고 글·사진을 고침. 사용자가 바꾼 사진·글은 그대로 씀. (11/23)
3. **확정 신호 = 표지 제목 입력**: 표지 장 `표지 제목:` 줄이 채워진 탭은 최종 합격. 렌더 결과를 사용자에게 보여 주지 않음. (11/23 사용자 "제목이 입력되면 최종 합격")
4. **확정 편 처리(같은 00:00 실행 안)**: 아직 업로드 대기열에 없는 확정 탭을 **제목이 입력된 가장 오래된 탭부터** 렌더 → 자동 규칙 점검 + ④ 별도 점검(고칠 게 있으면 고친 뒤 다시) → 업로드 대기열에 넣음. 탭 안의 진행 상태는 문서에 쓰지 않고 대기열 파일·기록에만.
5. **슬롯 배정**: 대기열에 들어가는 즉시 비어 있는 가장 빠른 슬롯. AI기업집중탐구 슬롯 = **02·06·10·14·18·22시 KST**(하루 최대 6편). 기업집중탐구 슬롯(00·04·08·12·16·20시)과 겹치지 않음. 이미 편이 배정된 슬롯은 건너뜀. (11/23)
6. **게시**: Aside가 사용자 PC의 instagram.com에서 **직접 게시**. 루틴은 각 슬롯 5분 뒤(**02:05·06:05·10:05·14:05·18:05·22:05**) 실행, `ai/schedule.json`에서 시각이 지난 편을 올림. Business Suite 예약은 인스타 캐러셀 10장 제한이라 쓰지 않음. 사용자 PC는 항상 켜져 있음. (11/23 기업집중탐구 첫 예약에서 8편 중 7편 막힘)
7. **기록**: 편마다 게시 결과를 기록(편·예정 시각·게시 시각·링크·장 수·결과·메모). 이미 게시된 편은 다시 하지 않음.

### 지키기
- 같은 편을 두 계정·두 슬롯에 올리지 않음. 게시 여부는 캡션 첫 줄로 확인하므로 게시된 편의 캡션 첫 줄은 바꾸지 않음.
- 장 수가 많아도 장을 빼거나 나누지 않음(원고 규칙상 최대 20장). 막히면 '확인 필요'.
- 업로드 파일 위치: 저장소 `ai/`(ai/posts/<편>/01.jpg… + caption.txt, ai/schedule.json). 기업집중탐구 파일(posts/·publisher/)은 건드리지 않음.
- 음악은 사용자가 직접(원고의 ■ 음악 추천을 기록 메모에 적음).

## A-3. 작업 구조 점검 (AI 쪽 Claude가 처음 한 번)
기업집중탐구 쪽이 11/23에 한 정리를 그대로 따라 함. 목적: 규칙이 여러 곳에 흩어져 옛 지시와 새 지시가 섞이는 걸 막고, 놓친 실수를 쓴 쪽이 아닌 점검자가 잡게 함. (11/23 사용자 "그쪽에서도 작업 구조 점검")

### 절대 지킬 것
- **이 합본(교과서)이 원본. AI 쪽에서 따로 규칙 파일을 만들거나 고치지 않음.** 고칠 일이 생기면 사용자에게 "교과서 변경 후보"로 알리고, 원본이 바뀌면 합본을 새로 받아 통째로 바꿈(합본 맨 위 '이번에 바뀐 것'을 보고 이미 만든 [AI] 탭에도 반영). (11/26)
- AI 쪽에서 고치는 건 AI만의 차이(②), 제작 과정(③), 디자인·업로드 규칙뿐.

### 순서 (한 번에 하나씩, 끝나면 사용자에게 한 줄)
1. **흩어진 규칙 위치를 전부 찾음**: 프로젝트 메모리, 스킬, 인수인계 파일, 공유 폴더의 지침·메모, Notion·구글 문서 탭, 예약 작업(트리거) 프롬프트, 스레드에서 사용자가 한 지적. 파일·줄 위치를 표로.
2. **흩어진 규칙은 지우고 이 합본만 가리키게 함**: 메모리·스킬·인수인계엔 '교과서 N장' 한 줄만. AI 쪽 렌더러 고유 설정(글꼴 경로 등)만 AI 쪽에 둠. (11/26)
3. **줄마다 날짜·예시**: 줄 끝 `(MM/DD 편 장)`. 한 편·한 장에만 해당하는 건 규칙이 아니라 파일 끝 **예외** 칸.
4. **업로드 규칙 맨 앞 줄 = 계정 확인**: 게시 화면에서 로그인된 계정이 AI기업집중탐구(@aicompany.focus)인지 확인한 뒤에만 누르고, 공유 직전 다시 확인. 다르거나 확인이 안 되면 멈추고 사용자에게. 이어서 흐름·슬롯: A-1(매일 00:00 실행, 02·06·10·14·18·22시 슬롯).
5. **피드백은 한 파일만**: 사용자 지적이 규칙이면 해당 파일 한 곳만 고치고(옛 줄 지움), 적은 문장을 사용자에게 한 줄로 돌려줌("이렇게 적었어요: ○○"). 고친 범위만, 넓힐지는 물어봄.
6. **쓴 쪽과 점검하는 쪽 분리**: 사용자에게 보이기 직전, 쓰지도 렌더하지도 않은 점검자(새 서브에이전트)가 규칙 파일과 한 줄씩 대조(10장 별도 점검 프롬프트, 점검 대상만 [AI] 탭으로). 점검자는 고치지 않고 표만.
7. **잴 수 있는 규칙은 자동 멈춤**: 있다/없다·개수·중복·목록 밖 단어(장 이름, 사진 설명 누락, 같은 사진 두 번, 금지 줄 💬📌👇, 맨 위 제목·상태 줄)는 스크립트가 검사해 걸리면 멈추게 함.
8. **옛 자료 보관**: 옛 지침·인수인계·메모는 보관 폴더(archive/날짜)로 옮기고 원래 자리엔 "→ 새 위치" 한 줄만. 인수인계 파일엔 **진행 중인 일만**.
9. **스킬·메모리는 위치만 가리킴**: 규칙 본문을 두지 않고 "규칙은 ○○ 폴더" 한 줄 + 순서만.
10. **한 편으로 먼저 시험**: 새 구조로 한 편을 처음부터 끝까지 만들어 보고, 막힌 곳만 고친 뒤 나머지 편에 적용.

### 끝나면
사용자에게: 찾은 규칙 위치 수, 지운 옛 줄 수, 새 파일 경로, 자동 멈춤 항목, 시험 편 결과를 짧게. 공통 규칙과 다른 점을 발견했으면 "공통 규칙 변경 후보"로 따로.
